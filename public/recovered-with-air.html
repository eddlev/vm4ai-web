Observed case study

Recovering from session loss — with AIR

Original incidents June 2026 · boundary notes updated August 2026

A continuity framework should be judged when the clean continuation path fails. During the AIR brand/site work, two project sessions stopped before a fresh Handoff Card had been saved.

In both observed incidents, available AIR state plus retained conversation history were sufficient to reconstruct a continuation record and resume without an observed information loss that blocked the project. That is an incident outcome, not a guarantee of exact state transfer, universal recoverability, or identical inference.

Two failures

  • A hard context limit. One session reached the point where it could no longer continue normally before a fresh Handoff was emitted.
  • A silent stall. Another session would begin responding and then stop without producing useful continuation output.

In each case, the ideal flow—make a current Handoff before the session becomes unusable—had already been missed.

How reconstruction worked

A fresh session used the AIR foundation and the available historical material as source input. The Handoff schema provided a structure for extracting project identity, active work, decisions, constraints, blockers, approvals, and continuation state instead of inventing a free-form summary.

The reconstructed transfer state was explicitly treated as reconstructed-from-history rather than as a live capture. The receiving session then used that state as continuation input rather than assuming the serialized card itself was execution authority.

Why the distinction matters

Current AIR 2.4.3 makes this boundary explicit: a Handoff Card is a TRANSFER_RECORD. Restored active state is a candidate for validation and rebinding. The receiving runtime must still establish a current valid Orbit 0 artifact before material execution continues.

That makes “we recovered the project” different from “the card proved every historical fact.” Project state restored from history remains declared/reconstructed state unless independently supported by source or tool evidence.

Not dependent on vendor history search

The incidents benefited from access to retained session history. That convenience is not the AIR mechanism. When history search is unavailable, a saved transcript or other retained source can be supplied to the receiving environment and used to reconstruct continuation state—provided the receiving host can process the material and the evidence/uncertainty boundary remains explicit.

The limit

If the relevant project state is gone—no current Handoff, no usable history, no retained transcript or other authoritative source—AIR cannot reconstruct information it does not have. The safest workflow is still proactive: refresh Handoff at meaningful boundaries before a session becomes fragile.

The takeaway

The useful result in these incidents was not “sessions cannot die.” They did. The result was that explicit project structure gave the recovery process a defined target and let a new session rebuild enough recorded state to keep the work moving.
