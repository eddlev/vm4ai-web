Before you rely on it

AIR is prompt-based and host-model governed. It adds structure, continuity and visible review boundaries, but it does not guarantee correctness or create deterministic backend enforcement. Check what matters.

Honest tradeoffs

AIR costs you something.

Structure is useful precisely because it adds constraints. That also means overhead.

More tokens, more steps

Scoping, state updates and review add turns compared with raw chat.

Overkill for quick answers

For one-off questions, raw chat is faster. AIR is built for sustained work where drift and lost state actually cost you.

Host capability still matters

Compatibility and quality depend on the platform and model running AIR. The framework does not erase host limitations.
