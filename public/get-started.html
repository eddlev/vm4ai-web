Get started

Boot AIR in minutes.

There is nothing to install and no AIR account to create. Bring a compatible AI host, the current AIR foundation, and a project you want to work on.

The short path

From files to active project.

This is the practical sequence. The reference pages explain the machinery behind it.

01

Get the current foundation

Open the AIR prompts directory and use the complete current foundation set. Do not mix prompt versions from different releases.

02

Open a fresh compatible AI session

Use a host that can accept the complete foundation without truncation. Context windows, file handling, higher-priority instructions, and model behavior vary, so compatibility is something to verify rather than assume.

03

Activate AIR

Attach the foundation files and type Start a new AIR project. The activation phrase starts AIR's validation/onboarding path; it does not silently answer the first onboarding choice for you.

04

Complete onboarding

AIR asks the current onboarding questions in order to establish the project, rigor, ambiguity handling, continuity preference, sources, responsibility split, delivery expectations, and approval boundaries.

05

Confirm the project is actually bound

A valid run surfaces the AIR records required by the current prompt contract and binds material execution to a current Orbit 0 artifact. If required load state or required records are missing, treat the run as non-conformant rather than filling the gap by assumption.

06

Work — then hand off when needed

AIR keeps the current material task explicit while the project moves. When the session ends or the work changes container, create a Handoff Card so a receiving compatible AIR session can validate, rebind, and continue from the recorded state.

If the boot looks wrong

Do not debug AIR from vibes. Check AIR load integrity for the conformance question, and Testing & Evidence for what the visible records can and cannot prove.
